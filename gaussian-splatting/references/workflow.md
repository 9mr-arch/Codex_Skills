# 이미지·영상 → Blender용 Gaussian PLY

## 수행 목표와 작업 권한

사용자가 첨부하거나 지정한 이미지·영상에서 실제 Gaussian Splatting 데이터를 만들고, Blender에서 불러와 색상과 형태를 확인할 수 있는 상태까지 완성한다. 설명이나 설치 명령만 건네지 말고 필요한 다운로드, 환경 구성, 코드 보완, 실행, 내보내기, 검수를 직접 수행한다.

이 스킬을 이용한 제작 요청에는 해당 작업에 필요한 무료 로컬 의존성, 모델 가중치, 실행 도구, Blender 및 호환 애드온 설치가 포함된다. 이미 작동하는 환경은 재사용하고 부족한 부분만 보완한다. 일상적인 설정값이나 무료 의존성 설치를 반복 확인하지 않는다. 플랫폼의 파일·네트워크·관리자 권한 절차는 준수한다. 유료 결제, 클라우드 업로드, 기존 데이터 삭제, 시스템 드라이버 교체나 재부팅은 별도 권한 없이 수행하지 않는다.

사용자에게는 존댓말로 현재 단계·발견한 문제·다음 조치를 간결하게 전달한다. 완료되지 않은 학습을 실행해 둔 것만으로 완료라고 말하지 않는다.

## 1. 입력과 작업 폴더 확정

1. 첨부 파일의 실제 경로 또는 사용자가 지정한 경로를 확인한다. 원본을 보존하고 `작업명_날짜` 형태의 새 작업 폴더를 만든다. 기존 결과가 있으면 재개 가능 여부를 확인하고 덮어쓰지 않는다.
2. 이미지 크기·EXIF 방향·색공간, 영상 길이·해상도·프레임률·회전 메타데이터를 조사한다. 영상은 처음·중간·후반과 장면 전환을 포함하는 콘택트시트를 만들어 직접 본다.
3. 대상이 특정 사물이면 사물 중심으로, 방·건물·공간이면 요청된 영역 전체로 처리한다. 대상이 모호한 경우 관찰 가능한 작업부터 진행하고 필요한 선택만 짧게 묻는다.
4. 작업 폴더에 `input_manifest.json`, `environment.json`, `run_config.json`, `logs/`, `checkpoints/`, `delivery/`를 둔다. 원본 경로·파일 해시·선택 구간·버전·명령·설정·진행 상태를 기록한다. 한글과 공백 경로는 UTF-8 및 안전한 인수 전달로 처리한다.

## 2. 입력별 복원 방식

### 이미지 한 장

단일 이미지에서 Gaussian을 직접 예측하는 로컬 모델을 사용한다. 우선 검토 대상은 [Apple SHARP 공식 저장소](https://github.com/apple-aiml-research/ml-sharp)이다. 실행 시점의 README, requirements, 모델 라이선스, CLI 도움말을 읽고 호환 환경에 설치한다. 공식 가중치를 내려받아 캐시한다. 설치한 CLI에서 지원 여부를 확인한 뒤 다음 형태로 실행한다.

```text
sharp predict -i INPUT_IMAGE_DIRECTORY -o OUTPUT_GAUSSIANS
```

결과를 `single_image_estimated`로 표시한다. 사진 한 장은 보이지 않는 뒷면·바닥·내부의 실측 정보를 제공하지 않는다. 기본 목표는 원본 시점과 가까운 시점에서의 입체감이며, 완전한 360도 스캔이라고 보고하지 않는다. 영상용 SfM에 동일 사진을 복제해 넣지 않는다. 생성형 멀티뷰로 뒷면을 채우려면 사용자가 그 방식을 원할 때만 수행하고 추정 영역을 명시한다. 단일 이미지 모델이 지원되지 않으면 같은 목적의 검증 가능한 로컬 대안을 조사하되 단순 RGB 점군을 Gaussian 결과로 대체하지 않는다.

### 여러 사진 또는 영상

실제 서로 다른 시점의 사진으로 카메라를 추정하고 3DGS를 학습한다. 사용자의 NullSplat 환경이 정상 작동하면 우선 재사용한다. 환경이 없거나 복구가 어려우면 COLMAP과 gsplat 기반의 유지보수되는 학습 구현 등 목적에 맞는 로컬 대안을 선택한다. gsplat 라이브러리만 설치해 학습 파이프라인이 완성됐다고 판단하지 말고 데이터 로더·초기화·학습·저장·렌더 경로를 함께 확인한다.

카메라가 거의 움직이지 않는 영상, 물체가 변형되는 영상, 회전하는 물체와 고정된 배경이 혼재하는 영상은 일반 정적 장면 SfM의 조건과 다르다. 시차·대상 움직임·배경 정합을 확인하고 구간 분리나 대상 마스킹을 적용한다. 문이 열린 상태와 닫힌 상태 등 서로 다른 상태는 별도 장면으로 처리한다. 정합이 불가능한 데이터를 성공한 360도 복원으로 표현하지 않는다.

## 3. 의존성 자동 설치와 환경 검증

먼저 OS, CPU, RAM, GPU 종류·총/여유 VRAM, 드라이버, 디스크 여유, Python/Conda, Blender 버전과 경로를 조사한다. 과거에 확인했던 GPU나 경로가 현재도 같다고 가정하지 않는다.

- 공통 도구: Git, FFmpeg/ffprobe, 격리된 Python 환경, 해당 구현의 requirements 또는 lockfile.
- 영상 복원: COLMAP, 선택한 PyTorch/CUDA 조합, 학습 구현, Gaussian 래스터라이저, 이미지·PLY 처리 라이브러리.
- 단일 이미지: 선택한 모델의 별도 환경과 공식 가중치. 영상 환경과 요구 버전이 다르면 환경을 분리한다.
- Blender: 기존 설치를 사용하고, 없으면 공식 배포본을 작업용으로 설치한다. 실제 Gaussian 표시를 지원하는 호환 애드온을 확인·설치한다.

공식 저장소·공식 배포처에서 버전과 설치 방법을 확인한다. 예전 프로젝트의 Python/Torch/CUDA 버전을 모든 환경에 고정 적용하지 않는다. 서로 다른 Conda 환경의 `site-packages`를 `sys.path`로 섞어 문제를 우회하지 않는다. 성공한 환경의 패키지 목록과 저장소 커밋, 모델 출처를 기록한다.

Windows의 gsplat은 [공식 Windows 설치 문서](https://github.com/nerfstudio-project/gsplat/blob/main/docs/INSTALL_WIN.md)를 확인한다. Python·Torch·CUDA가 맞는 공식 사전 빌드 휠을 우선 검토하고, 소스 빌드가 필요하면 CUDA Toolkit, MSVC Build Tools, Windows SDK 등 실제 요구 도구를 설치한다. 컴파일 환경 변수는 실행 프로세스 범위에 적용한다. GPU 아키텍처 지원 여부도 확인한다.

설치 완료 판정은 import 성공만으로 끝내지 않는다. CUDA 텐서 연산, 소수 Gaussian의 forward 렌더, 학습 경로의 backward 1회, PLY 쓰기·다시 읽기, Blender 실행을 작은 데이터로 확인한다. 실패 시 오류 종류를 구분해 호환 버전·컴파일 환경·패키지를 수정한다. 같은 오류에 같은 명령을 무한 반복하지 않는다. GPU가 없으면 모델이 지원하는 CPU/MPS 경로를 검토하고 성능과 지원 범위를 보고한다.

## 4. 프레임 선택과 카메라 정합

전체 시간 범위에서 선명한 프레임을 뽑는다. 초반만 사용하거나 일괄 장수 제한 때문에 후반부를 누락하지 않는다. 초기 간격은 움직임에 따라 약 0.2–1초에서 선택하되 인접 시점의 충분한 겹침, 시차, 대상의 앞뒤·위쪽·세부 시점 보존을 우선한다. 흔들린 프레임은 근처의 선명한 프레임으로 교체한다. 길거나 반복적인 영상은 시간별·시점별로 균형 있게 줄인다.

원본 프레임 번호·시간·선명도·학습 파일명을 대응시킨다. 회전 메타데이터와 렌즈 왜곡을 올바르게 처리한다. 흐릿한 입력을 생성형 보정해 새로운 무늬를 만든 뒤 실측처럼 학습하지 않는다.

영상에는 순차 매칭과 필요 시 루프 클로저, 비연속 사진에는 적절한 전체/검색 기반 매칭을 사용한다. 정합 후 다음을 확인한다.

- 선택 프레임 수와 등록 수, 시간 구간별 등록 비율, 가장 긴 미등록 구간.
- 연결된 모델 수, 카메라 궤도, 재투영 오차, 실제 대상 주변 점 분포.
- 요청된 뒷면·후반 구간이 같은 모델 안에 들어갔는지.

높은 전체 등록률만으로 성공 판정하지 않는다. 중요한 시점이 빠지면 해당 구간의 샘플링·매칭·카메라 모델을 개선한다. 연결되지 않는 구간은 별도 모델로 전달하거나 타당한 공통 기준으로 정합한다. 임의 위치에 겹쳐 병합하지 않는다. 왜곡을 보정한 학습 이미지에는 그 이미지에 대응하는 카메라 내부 파라미터를 사용한다.

## 5. 메모리 예산과 학습

해상도·프레임 수·Gaussian 상한·밀도 증가 종료 시점을 현재 여유 VRAM에 맞춘다. 예를 들어 단일 사물은 긴 변 960–1600px, 200–600개 프레임, batch 1, 최대 50만–200만 Gaussian 범위에서 시작할 수 있지만 이는 고정 요건이 아니다. 예비 실행 100–500회로 실제 메모리 사용량과 속도를 측정해 조정한다. 시작 전에 디스크와 체크포인트 저장 공간도 확보한다.

최대 점 수가 초기 seed에만 적용되는지 확인하고 밀도 증가 단계에도 실제 상한을 적용한다. 다른 앱이 사용할 VRAM 여유를 남긴다. 입력 전부를 GPU에 상주시켜 메모리를 소모하지 않도록 로더를 확인한다. 30,000–50,000회 등의 반복 수는 장면 복잡도와 수렴을 보고 정하며 숫자 달성 자체를 품질 기준으로 삼지 않는다.

로그와 복구 가능한 체크포인트를 주기적으로 저장한다. PLY만으로 재시작하면 optimizer 상태가 복원되지 않을 수 있으므로 재개 형식을 구분한다. Windows 백그라운드 실행은 숨김 창과 stdout/stderr 로그, PID를 사용한다. 프로세스 생존, 로그 증가, 학습 단계, GPU 메모리와 오류를 확인하며 완료까지 이어간다.

OOM은 원인을 확인한 뒤 해상도·메모리 적재·밀도 증가·상한 순서 중 효과적인 조합을 조정한다. 오류가 반복되면 마지막 성공 단계에서 다른 유효 설정으로 재개한다. 학습된 원본은 보존하고 후처리는 복사본으로 수행한다.

## 6. 대상 분리와 정리

사물 요청은 원본 전체 장면과 대상 중심 정리본을 구분한다. 공간 요청은 벽·바닥·천장을 임의로 제거하지 않는다. 객체 마스크를 활용할 때는 원본/왜곡 보정 이미지 좌표를 맞추고 여러 시점으로 대상과 배경을 구분한다.

정리 범위는 컬러 점군, 카메라 투영, 실제 렌더로 결정한다. 좌표축의 위·아래 부호나 카메라 궤도 중심만 믿어 자르지 않는다. 축별 색상 단면과 원본 화면을 함께 확인하고, 바닥·목·얇은 장식·입구의 범위를 직접 검증한다. 단일 사진에서는 작은 시점 변화에서도 경계가 보존되는지 본다.

Gaussian 중심뿐 아니라 크기·회전·불투명도와 실루엣 기여를 고려한다. 가장 큰 연결 요소만 남기는 방식은 대상 일부를 지울 수 있다. 보수적으로 정리하고 잘림이 보이면 컷을 수정한다. 제거 전후 동일 카메라 렌더를 비교한 후보만 최종본으로 확정한다. 숨겨진 바닥이나 불확실한 내부를 임의 메시로 채우지 않는다.

## 7. PLY 및 컬러 호환 출력

반드시 실제 Gaussian 파라미터가 있는 `이름_gaussian.ply`를 만든다. 일반적인 3DGS PLY는 `x/y/z`, `f_dc_*`, 사용 차수에 맞는 `f_rest_*`, `opacity`, `scale_0..2`, `rot_0..3`를 포함한다. 필드 이름만 맞추지 말고 학습기와 로더의 인코딩을 확인한다. 표준 형식에서는 scale이 로그값, opacity가 logit일 수 있고 quaternion 순서와 SH 배열 순서도 구현별로 검증해야 한다.

색상 검증용 `이름_blender_rgb.ply`도 생성한다. 표준 3DGS DC 계수라면 `RGB = clamp(0.5 + 0.28209479177387814 * f_dc, 0, 1)`로 RGB를 계산하고 0–255 색상 속성으로 기록한다. 모델 출력이 이미 RGB이거나 다른 인코딩이면 해당 공식으로 재변환하지 않는다. RGB 파일은 점군 호환본이며 원본 Gaussian의 SH·타원체·투명도 표현을 모두 대신하지 않는다. 뷰어가 필요로 할 때 `.splat` 등을 추가한다.

NaN/Inf, 점 개수, 속성 개수, 데이터 바이트 길이, quaternion 정상성, 색상 분포, 투명도, bounding box를 검사한다. SH0 및 SH3처럼 서로 다른 차수와 추가 메타데이터를 올바르게 처리한다. 내보낸 파일을 다시 읽고 렌더해 채널·축·크기 오류를 확인한다.

## 8. Blender에서 실제 사용 검수

Blender 기본 PLY 가져오기만으로 Gaussian의 크기·회전·투명도·시점 의존 색상이 자동 렌더된다고 설명하지 않는다. 현재 Blender 버전과 호환되는 실제 Gaussian 가져오기/렌더 애드온의 공식 문서와 구현을 확인한다. 설치한 애드온이 SH 차수, scale/opacity 인코딩, 회전 순서, 좌표계, 렌더 엔진을 어떻게 처리하는지 확인하고 지원 한계를 기록한다. 이름이나 API를 추측해 실행하지 않는다.

별도의 검사 장면에서 권장 Gaussian PLY를 가져온다. 중심·방향·크기를 맞추고 카메라·배경을 설정해 컬러 렌더를 만든다. 색이 검거나 점만 보이면 SH/RGB, 색 관리, 재질, 애드온 사용 경로를 확인한다. 실제 미터 크기는 근거가 있는 경우에만 사용하며 추정 스케일이면 표시한다. 변환은 우선 Blender 오브젝트 변환으로 적용한다. PLY 좌표를 직접 회전한다면 Gaussian quaternion 및 SH 방향 성분도 올바르게 변환해야 한다.

Blender 컬러 점군 확인용 재질은 가져온 색상 속성의 실제 이름·도메인을 조사해 연결한다. 많은 점을 개별 오브젝트나 고해상도 구로 만들지 않는다. 필요하면 Geometry Nodes와 인스턴싱으로 가벼운 점군 미리보기를 만든다. 이 미리보기는 실제 Gaussian 렌더와 명확히 구분한다.

가능하면 검증한 `이름_preview.blend`와 미리보기 이미지를 함께 저장한다. Blender 설치·애드온이 지원되지 않으면 표준 Gaussian PLY와 RGB PLY를 완성하고 다른 Gaussian 렌더러로 검수한다. 이 경우에는 “Blender 검수 완료”라고 하지 말고 남은 호환 문제와 사용할 파일을 정확히 전달한다.

## 9. 품질 확인과 완료 기준

영상 결과는 앞·뒤·좌우·위쪽과 영상 전·중·후반 등 대표 8–12개 시점에서 비교한다. 가능하면 학습에서 제외한 시점이나 가까운 보간 시점도 검사한다. 단일 이미지는 원본 시점과 작은 카메라 이동을 검수하고 보이지 않는 뒷면을 평가 대상에 억지로 포함하지 않는다.

문양·색상·얇은 부분·바닥 경계·입구·요청 구간 누락·떠다니는 잔여물·이중 표면을 직접 본다. PSNR 등 수치를 쓸 때 학습/보류 시점을 구분한다. 배경을 지운 결과를 배경이 남은 전체 원본과 비교한 PSNR을 대상 품질 점수로 제시하지 않는다. 동일 대상 마스크를 쓰거나 원본 장면 점수와 정리본 시각 검수를 분리한다.

`delivery/`에는 다음을 모은다.

- 권장 Gaussian PLY, Blender RGB PLY, 필요 시 웹용 SPLAT.
- 검증한 Blender 장면과 실제 렌더 미리보기. 생성하지 못한 항목은 누락 이유를 명시한다.
- 원본 전체 장면 Gaussian 또는 보존 위치.
- `README_KO.md`: 열어야 할 파일, Blender 버전·애드온·가져오기 절차, 지원되는 표현과 제한.
- `manifest.json`: 입력·모델·버전·실행 설정·정합 범위·학습 단계·포인트 수·정리 방법·검수 결과·파일 크기·SHA-256·좌표/스케일 정보.

검수에서 탈락한 후보는 최종 추천 파일로 안내하지 않는다. 사용자 데이터나 복구 가능한 결과를 임의 삭제하지 않는다. 최종 파일의 해시가 검수한 파일과 같은지 대조한다.

최종 응답에는 바로 사용할 PLY 링크와 검수 이미지, 주요 제한만 간단하게 전달한다. 파일 생성, Gaussian 렌더 검증, Blender 가져오기 검증을 각각 실제 수행한 수준으로 구분한다. 이 스킬은 실행 지침이며 어떤 입력에서나 완전한 360도 모델을 보장하는 실행 프로그램은 아니다.
